1. PROJECT TITLE
--------------------------------------------------------------------------------

MyLibrary - A Digital Library Management System using Flask and MongoDB


--------------------------------------------------------------------------------
2. INTRODUCTION
--------------------------------------------------------------------------------

MyLibrary is a web-based library management system for a college library.
It helps the librarian keep book records, register students, issue books,
and record returns on a website instead of a paper register.

The home page of the website opens the book catalog. All data is stored in
a MongoDB database named library_db. The browser shows HTML pages styled
with CSS. A small JavaScript file is used only for the mobile menu and to
close flash messages.

This project is made for academic and educational use.


--------------------------------------------------------------------------------
3. OBJECTIVES
--------------------------------------------------------------------------------

The main objectives of MyLibrary are:

  1. To display the library book collection on a website.
  2. To search books by title or author and filter them by genre and
     availability (In Stock / Out of Stock).
  3. To add new books, update stock (restock), and remove books.
  4. To register students and store name, class, and email.
  5. To issue a book to a student and reduce the book quantity by one.
  6. To return a book and increase the book quantity by one.
  7. To prevent issuing a book when quantity is zero (out of stock).
  8. To keep a record of issue date and return date.

5. FEATURES (WHAT THE SYSTEM CAN DO)
--------------------------------------------------------------------------------

A. BOOK CATALOG (HOME / CATALOG PAGE)
   - Opening / redirects to /books (the catalog).
   - Books are shown in a card grid with cover image, title, author,
     genre, stock status, and remaining quantity.
   - Search by title or author.
   - Filter by genre (genres taken from the books stored in MongoDB).
   - Filter by availability: In Stock or Out of Stock.
   - Pagination: 12 books per page, with Previous and Next when needed.
   - The page shows total titles in the library and how many match the
     current search or filter.
   - Each card has Issue / View, Restock, and Remove.

B. ADD BOOK
   - Form fields: Title, Author, Genre, Quantity, optional Cover Image URL.
   - After a successful save, the new book appears in the catalog.

C. RESTOCK (UPDATE QUANTITY)
   - Restock page shows the current quantity and In Stock / Out of Stock.
   - The librarian enters a new quantity (0 or more).
   - Quantity 0 means Out of Stock. Quantity 1 or more means In Stock.

D. REMOVE BOOK
   - Remove deletes the book after confirmation.
   - Related issue/return records for that book are also deleted.

E. STUDENTS
   - Students page lists Student ID, Name, Class, and Email.
   - Add Student form fields: Name, Class, and Email.

F. ISSUE BOOK
   - On Issue / Return, the user selects an in-stock book and a student.
   - The system stores the issue with today's date and return_date empty.
   - Book quantity is reduced by 1.
   - A book with quantity 0 cannot be issued.

G. RETURN BOOK
   - Recent records (up to 50) are listed with issue date and return date.
   - If the book is not yet returned, a Return button is shown.
   - Return sets today's date as return_date and increases quantity by 1.
   - An already returned record cannot be returned again.

H. NAVIGATION, MESSAGES, AND LAYOUT
   - Navbar: Catalog, Students, Issue / Return, Add Book, Add Student.
   - The logo name is MyLibrary. The logo link goes to home (/), which
     redirects to the catalog.
   - On small screens the menu uses a hamburger button.
   - Flash messages show success or error after form actions.
   - Footer shows MyLibrary, college context (Second Year BCS, Jijamata
     College of Science and Arts, Bhende), and developer name Om Shelke.
   - Pages work on desktop, tablet, and mobile (responsive CSS).

6. MONGODB DATABASE AND COLLECTIONS
--------------------------------------------------------------------------------

Database name: library_db

Collections used by the application:

  1. books
     Fields used: book_id, title, author, genre, quantity,
     cover_image_url, created_at
     quantity greater than 0 = In Stock; quantity 0 or less = Out of Stock

  2. students
     Fields used: student_id, name, class, email, created_at

  3. issue_return
     Fields used: record_id, book_id, student_id, issue_date,
     return_date, created_at
     return_date is empty (null) until the book is returned

  4. counters
     Used internally to generate the next integer book_id, student_id,
     and record_id (similar to auto-increment numbers)

Indexes are created on book_id, title, author, genre, student_id,
record_id, and the book_id / student_id fields in issue_return.

7. IMPORTANT FLASK ROUTES
--------------------------------------------------------------------------------

  GET  /                         Home; redirects to the catalog
  GET  /books                    Catalog with search, genre, availability,
                                 and pagination
  GET, POST /books/add           Add a new book
  POST /books/<book_id>/remove   Remove a book
  GET, POST /books/<book_id>/restock
                                 View or update book quantity
  GET  /students                 List registered students
  GET, POST /students/add        Register a new student
  GET, POST /issue-return        Issue a book or return a book;
                                 show recent records

Main Python files:
  app.py       - Flask routes and form handling
  database.py  - All MongoDB read and write operations
  config.py    - MongoDB URI, database name, secret key, 12 books per page

9. WORKING PROCESS (HOW THE SYSTEM WORKS)
--------------------------------------------------------------------------------

  1. The user starts MongoDB locally and runs: python app.py
  2. The browser opens http://127.0.0.1:5000
  3. Flask sends the request to the matching route in app.py
  4. app.py calls functions in database.py
  5. database.py reads or writes documents in MongoDB (library_db)
  6. Flask renders an HTML template with the data
  7. CSS styles the page; JavaScript only opens the mobile menu and
     closes flash messages
  8. When a book is issued, quantity decreases. When it is returned,
     quantity increases. The catalog then shows In Stock or Out of Stock

There is no login page in the current project. Any user of the running
website can use the catalog, student, and issue/return pages.
